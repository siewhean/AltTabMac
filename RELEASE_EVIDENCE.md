# CmdTab Release Evidence Contract

`./scripts/aggregate_release_evidence.sh` is the final pre-publication gate. Every receipt must contain the canonical `sourceCommit` and `releaseTag`; copied screenshots, prose, or an unlinked test run are not substitutes.

## Automated Receipts

- App notarization: `CmdTab-<version>-release-receipt.json`, produced by `build_release_dmg.sh` and revalidated by `verify_release_artifacts.sh`.
- Preview deploy: `CmdTab-<version>-preview-deployment.json`, with `environment: "preview"` and `healthStatus: "passed"`.
- Preview smoke: `CmdTab-<version>-preview-smoke.json`, generated by `run_preview_smoke.sh`. It verifies unauthorized cron, invalid and replayed signed webhook handling with fixture cleanup, trial/checkout/license URL wiring and reachability, dashboard authentication, and shared Redis limits without retaining customer data.
- Production staging: `CmdTab-<version>-production-staging-deployment.json`, with protected access verified, no aliases, and healthy Production configuration. It is not canonical or public release evidence.
- Neon recovery: `neon-recovery-receipt.json`, generated only by `capture_neon_recovery_evidence.mjs` from authenticated Neon API responses. It binds the production project and branch to a protected recovery checkpoint branch, provider-assigned parent LSN, completed operation IDs, response hashes, and `history_retention_seconds >= 604800`. Missing credentials, failed operations, insufficient retention, or an unverified checkpoint fail closed. See the official [project](https://api-docs.neon.tech/reference/getproject), [branch](https://api-docs.neon.tech/reference/getprojectbranch), and [operation](https://api-docs.neon.tech/reference/getprojectoperation) APIs.
- Database migration: `production-migration-receipt.json`, with `ok: true` and a `neonRecoveryEvidence` binding whose SHA-256 and resource IDs match `neon-recovery-receipt.json`.
- Environment/WAF: `CmdTab-<version>-environment-validation.json`, with `ok`, `previewProductionSeparated`, and `wafEnforced` all `true`.
- Backup/restore: `backup-restore-receipt.json`, generated by the protected `CmdTab Backup Restore Release Evidence` workflow from the real backup, restore, and Production migration artifacts. It binds their run IDs and receipt SHA-256 values, derives PITR duration only from the Neon receipt, and records the verified backup SHA-256.

## Runtime Receipt

`runtime-qa-receipt.json` is the successful JSON summary from `validate_runtime_qa.sh`, augmented with the canonical `sourceCommit` and `releaseTag`. It must contain `passed: true`, no failures, at least 100 warm sessions, 20 cold sessions, 100 exact-window activations in 100 multi-window sessions, 200 forward and 200 reverse steps, callback samples, and results at or inside every threshold: `warmPostDeadlineP95Milliseconds <= 50`, `warmPostDeadlineMaximumMilliseconds <= 100`, `callbackP95Milliseconds <= 5`, `callbackMaximumMilliseconds < 20`, and `coldTotalP95Milliseconds <= 250`.

## Clean-Mac Receipts

`clean-mac-arm64-qa-receipt.json` and `clean-mac-x86_64-qa-receipt.json` require `ok: true`, `cleanMac: true`, the matching `architecture`, `macOSMajor >= 13`, and the notarized artifact SHA-256. Their `checks` object must set every field to `true`: `gatekeeper`, `dragInstall`, `permissionGrantDenyRevokeRecovery`, `launchAtLogin`, `secureInput`, `spaces`, `fullscreen`, `multipleDisplays`, `licensing`, and `telemetryOptOut`.

## Independent QA Receipt

Generate `final-qa-receipt.json` only after the independent review with `CMDTAB_FINAL_QA_REVIEWER`, `CMDTAB_FINAL_QA_REPORT_ID`, and `CMDTAB_FINAL_QA_FINDINGS=0 node scripts/generate_final_qa_receipt.mjs`. The generator hashes every preceding receipt, records its concrete artifact/deployment/run evidence identifier, and timestamps the review after all evidence. The aggregator independently recomputes those bindings and rejects missing, changed, forged, future, or prematurely reviewed evidence.

The protected, self-hosted `CmdTab Prepublication Evidence Intake` workflow is the only accepted producer of the complete input bundle. A reviewer stages the receipts and DMG in the protected runner directory, approves the `production-release-evidence-intake` environment, and the workflow uploads the fixed artifact `cmdtab-prepublication-evidence-<run-id>`. `CmdTab Final Release Evidence` verifies that producer run's exact workflow path, successful completion, dispatch event, and tagged source SHA before downloading it. It then runs the aggregate command and uploads the aggregate, checksum, notarized DMG, and every hash-bound input as `cmdtab-release-evidence-<run-id>`. It deliberately excludes public Blob and canonical-promotion receipts to avoid circular evidence.

## Public Release

`CmdTab Public Release` accepts only a successful `CmdTab Final Release Evidence` workflow run for the tagged SHA. Both public scripts recompute every bound receipt hash. The first publishes the notarized DMG to an immutable version-and-SHA path and re-downloads it; the second durably records the current canonical deployment, promotes only the authorized staging deployment, confirms the alias and `https://cmdtab.net/api/health`, and automatically restores and verifies the recorded target if promotion validation fails.
